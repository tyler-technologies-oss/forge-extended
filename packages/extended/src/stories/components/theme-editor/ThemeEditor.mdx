<Title />

A complete authoring surface for a Tyler Forge™ theme. It edits all 101 `--forge-theme-*` design tokens,
derives a full palette from a handful of seed colors, reports the worst `on-*` contrast ratios, imports and
exports the theme, and can apply the theme to the live page so a customer can see it on the real product.

The component owns no persistence. It edits a theme object and emits it; the host application decides where
that theme is stored and how it is delivered.

## Usage

```html
<forge-theme-editor>
  <span slot="title">Brand theme</span>
</forge-theme-editor>
```

```ts
const editor = document.querySelector('forge-theme-editor');

editor.loadTheme(await fetchSavedTheme());
editor.addEventListener('forge-theme-editor-change', ({ detail }) => save(detail.theme));
```

### Views

The views are in authoring order, and the editor opens on **Palette** — seed a palette
first, then fine-tune individual tokens, then check contrast, then take the theme away
with you.

- **Palette** — pick the nine seed colors and the editor derives the container ramps, the readable `on-`
  inks, and the surface, text and outline scales. `Surface` chooses light or dark, and it is the palette
  that owns that choice (see [Light and dark](#light-and-dark)). `Target contrast` is the WCAG ratio
  derived inks aim for; turning off `Pure black/white accent inks` derives tinted inks instead of the pure
  black and white that Forge's own tokens use. `Target contrast` offers the three ratios WCAG 2 actually
  defines (3:1, 4.5:1, 7:1) rather than a free-form number.
- **Tokens** — every token, grouped into cards (brand, primary, secondary, tertiary, surface, text,
  success, error, warning, info, outline). Each group header carries a swatch of the color it is about, and
  each row a color swatch and a text field. The filter narrows to matching token
  names or group labels, and matched groups expand automatically. Each row has its own revert button, and
  `Revert all` clears every override at once. A `Global knobs` panel exposes `--forge-shape-factor`,
  a spacing multiplier, and the typography font family and size.
- **Contrast** — Forge pairs every surface token with an `on-` token, and that is the color it draws text
  and icons in on top of that surface. Each row **renders the pair for real** next to its ratio, so an
  illegible combination is visible rather than inferred from a number. Body text needs 4.5:1 and large text
  3:1 for WCAG 2 AA. Some targets are physically unreachable — nothing contrasts 7:1 with a mid-lightness
  orange — so the report shows the shortfall rather than pretending it passed.
- **Import & export** — export as JSON, as Sass built on Forge's own `theme.provide()` mixin, or as a plain
  `:root` CSS block. Import accepts pasted JSON or a dropped file. Unknown token names are **rejected and
  reported** rather than imported, because an invalid name emits a `--forge-theme-*` property that nothing
  reads.

### Light and dark

A theme is **two independent designs**, not one design with a switch. An accent that
reads well on white is usually wrong on near-black, so the editor keeps a separate
variant per polarity — its own token overrides and its own seed colors:

```ts
theme.polarity; // 'light' | 'dark' — which variant is being authored
theme.variants.light; // { tokens, seeds }
theme.variants.dark; // { tokens, seeds }
```

Editing `primary` in light does not touch dark, and switching back finds your light
work exactly as you left it. `Surface` on the **Palette** view switches variants; it
derives nothing on its own. A variant you have never touched is seeded from that
polarity's stock Forge colors, so starting a dark theme starts from Forge's dark
palette rather than from light accents on a dark surface.

`mode` is a separate question — what to _emit_, not what to design:

| `mode`    | Emits                                                              |
| --------- | ------------------------------------------------------------------ |
| `patch`   | only the tokens you changed, so the host app's theme shows through |
| `replace` | the stock set for the active polarity, then your changes on top    |

Generating a palette sets `mode` to `replace`, because 101 tokens is a whole theme
rather than a patch. Exported JSON always carries **both** variants, so one file is
the complete light-and-dark design.

### Staying readable while previewing

`immuneToPreview` (on by default) keeps the editor's own chrome on the host
application's theme while a page-wide preview is applied.

Without it the tool inherits the theme being authored — fine until you author
something low-contrast, at which point you cannot see well enough to fix it. The
component samples the page's own tokens before injecting the override and re-declares
them on itself; an inline `!important` declaration outranks the preview's `!important`
rule on `:root`/`body` for this element and its subtree. Set
`immune-to-preview="false"` to have the editor restyle along with the page.

### Sizing

The token list tiles into as many columns as the container allows, because a token value is
a hex code rather than prose. Three custom properties tune it:

| Custom property                     | Default | Purpose                                        |
| ----------------------------------- | ------- | ---------------------------------------------- |
| `--_forge-theme-editor-cell-min`    | `232px` | Minimum width of a token cell before it wraps. |
| `--_forge-theme-editor-max-height`  | `80dvh` | Height the editor scrolls within.              |
| `--_forge-theme-editor-swatch-size` | `28px`  | Size of the color swatch button.               |

The header and the tab bar stay put while the active view scrolls.

### The live preview

`Preview on page` applies the theme to the whole document, and the button, a banner, and the reflected
`preview` attribute all make the live state obvious. Toggling it off removes the injected stylesheet and the
application returns to its own theme.

The preview has to be written as real CSS, because there is no Forge machinery that turns a theme object into
custom properties: Forge emits the light set from `forge.css` as `:root { @include theme.properties; }`, and
the dark set ships only as the `theme-dark.theme-properties` mixin, which host applications attach to a
selector themselves.

That is also why the preview declares its tokens on a list of selectors with `!important`:

```css
:root,
body,
.dark-theme,
.light-theme,
.app-theme-dark,
.app-theme-light,
[data-forge-theme='dark'],
[data-forge-theme='light'] {
  --forge-theme-primary: #b3001b !important;
}
```

Host applications conventionally declare the dark set on a class on `<body>`, and a custom property declared
on `<body>` beats one inherited from `:root`. Declaring at `:root` alone therefore loses on any page already
in dark mode. Declaring on the conventional carriers as well, with `!important`, beats any non-important
author rule on the same element regardless of specificity, and interoperates with both the class convention
and `forge-theme-toggle`'s `data-forge-theme` attribute. Set `previewSelectors` to target a different carrier
instead.

Custom properties inherit through shadow boundaries, so overriding them on `<body>` reaches inside every
Forge web component's shadow root too.

## API

<CustomArgTypes />

### Properties

| Name               | Type                        | Default                         | Description                                                   |
| ------------------ | --------------------------- | ------------------------------- | ------------------------------------------------------------- |
| `theme`            | `ForgeTheme`                | an untouched theme              | The theme being edited. Set as a property, not an attribute.  |
| `preview`          | `boolean`                   | `false`                         | Whether the theme is applied to the live document. Reflected. |
| `previewSelectors` | `string[]`                  | the conventional theme carriers | The selectors the live preview declares its tokens on.        |
| `immuneToPreview`  | `boolean`                   | `true`                          | Keeps the editor on the host app's theme while previewing.    |
| `exportFormat`     | `'json' \| 'scss' \| 'css'` | `'json'`                        | The export format shown on the import and export view.        |
| `theme.polarity`   | `'light' \| 'dark'`         | `'light'`                       | Which variant is being authored.                              |

### Methods

| Name                      | Description                                                                 |
| ------------------------- | --------------------------------------------------------------------------- |
| `getTheme()`              | Returns the theme being edited.                                             |
| `loadTheme(theme)`        | Replaces the theme, filling in anything the value omits.                    |
| `applyPreview()`          | Applies the theme to the live document.                                     |
| `removePreview()`         | Removes the theme from the live document.                                   |
| `getPreviewCss()`         | Returns the CSS the preview injects, whether or not the preview is applied. |
| `exportTheme(format?)`    | Emits the theme as JSON, Sass or CSS.                                       |
| `importTheme(text)`       | Imports theme JSON and returns the warnings raised.                         |
| `generatePalette(seeds?)` | Derives the full token set from seed colors.                                |
| `setToken(token, value)`  | Sets one token, or clears it when the value is empty.                       |
| `resetToken(token)`       | Reverts one token to the Forge default for the theme's mode.                |
| `resetAllTokens()`        | Reverts every token.                                                        |
| `getContrastReport()`     | Returns every `on-*` pair and its contrast ratio, worst first.              |

### Events

| Name                         | Detail                                         | Description                                                                                                      |
| ---------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `forge-theme-editor-change`  | `{ theme: ForgeTheme, token: string \| null }` | Fired when the theme is edited. `token` names the edited token, or is `null` when the whole theme changed.       |
| `forge-theme-editor-preview` | `{ preview: boolean, css: string }`            | Fired when the live preview is toggled. `css` is the injected stylesheet, or empty when the preview was removed. |
| `forge-theme-editor-import`  | `{ theme: ForgeTheme, warnings: string[] }`    | Fired when a theme is imported.                                                                                  |

All three events bubble, are composed and are cancelable.

## Accessibility

- Every color swatch and text field is labelled with the token it edits, and every revert button carries an
  `aria-label` naming its token.
- The preview button reports its state with `aria-pressed`, and the live preview is also announced by a
  banner inside the editor.
- Each view is a labelled `region`.
- The contrast view exists so that an authored theme can be checked against WCAG 2 AA before it ships. A
  theme that fails there will be illegible for some users no matter how the editor is operated.
