The `<forge-rich-text-editor>` component provides a powerful and accessible rich text editing experience powered by [TipTap](https://tiptap.dev/). It offers a flexible, component-based architecture where editing features are added as child components, allowing you to compose exactly the functionality your application needs.

The editor supports both standalone usage (with toolbar inline) and composed usage (with toolbar separated from content), making it adaptable to various UI layouts.

## Usage

The rich text editor follows a compositional pattern where you add feature components as children. Each feature component provides specific editing capabilities and registers itself with the editor:

```html
<forge-rich-text-editor>
  <forge-rte-standard-tools></forge-rte-standard-tools>
  <forge-rte-feature-divider></forge-rte-feature-divider>
  <forge-rte-code></forge-rte-code>
  <forge-rte-link></forge-rte-link>
</forge-rich-text-editor>
```

### Available Features

#### Standard Tools (`<forge-rte-standard-tools>`)

The standard tools component provides common formatting features:

- **Bold**: Apply bold formatting to selected text
- **Italic**: Apply italic formatting to selected text
- **Underline**: Apply underline formatting to selected text
- **Strikethrough**: Apply strikethrough formatting to selected text
- **Bulleted List**: Create unordered lists
- **Numbered List**: Create ordered lists
- **Headings**: Format text as heading levels 1, 2, or 3
- **Text Alignment**: Align text left, center, right, or justify

The standard tools component exposes each feature through properties that allow you to customize labels for accessibility:

```html
<forge-rte-standard-tools
  bold-label="Make text bold"
  h1-label="Large heading"
  h2-label="Medium heading"
  h3-label="Small heading"
  align-left-label="Align left"
  align-center-label="Align center"
  align-right-label="Align right"
  align-justify-label="Justify text">
</forge-rte-standard-tools>
```

#### Additional Features

- **Code** (`<forge-rte-code>`): Inline code formatting
- **Link** (`<forge-rte-link>`): Insert and edit hyperlinks
- **Divider** (`<forge-rte-feature-divider>`): Visual separator between feature groups

### Headings Feature

The rich text editor supports three levels of headings (H1, H2, H3) through the standard tools component. Each heading level has:

- A dedicated button with a unique icon
- Active state indication when the cursor is in a heading
- Customizable accessible labels
- Toggle behavior (clicking the active heading button converts back to paragraph)

Headings follow proper semantic HTML structure and can be styled consistently with your application's typography system.

### Composed Layout

For more complex layouts where you want to separate the toolbar from the content area, use the `<forge-rich-text-context>` component:

```html
<forge-rich-text-context>
  <forge-card class="toolbar" raised>
    <forge-rte-standard-tools></forge-rte-standard-tools>
  </forge-card>
  <forge-card class="content-card" raised>
    <forge-rich-text-content></forge-rich-text-content>
  </forge-card>
</forge-rich-text-context>
```

This pattern is useful for fixed toolbars, multi-column layouts, or when you need precise control over toolbar placement.

### Events

The editor emits a `change` event whenever the content is modified:

```javascript
const editor = document.querySelector('forge-rich-text-editor');
editor.addEventListener('change', evt => {
  console.log('Editor content:', evt.detail);
});
```

### Rendering Content

Use the `<forge-rich-text-renderer>` component to display rich text content in a read-only format:

```html
<forge-rich-text-renderer></forge-rich-text-renderer>
```

## Accessibility

The rich text editor is designed to meet WCAG 2.1 Level AA compliance with comprehensive keyboard navigation, screen reader support, and proper ARIA semantics.

### Keyboard Navigation

All editor functionality is accessible via keyboard without requiring a mouse. The editor supports standard Tab navigation through toolbar buttons and intuitive keyboard shortcuts for formatting.

#### Navigation Shortcuts

| Shortcut           | Action                                      |
| ------------------ | ------------------------------------------- |
| `Tab`              | Move to next toolbar button or content area |
| `Shift+Tab`        | Move to previous element                    |
| `Enter` or `Space` | Activate focused toolbar button             |
| `Escape`           | Close link popover                          |

#### Text Formatting Shortcuts

| Windows/Linux  | macOS         | Action                 |
| -------------- | ------------- | ---------------------- |
| `Ctrl+B`       | `Cmd+B`       | Toggle bold            |
| `Ctrl+I`       | `Cmd+I`       | Toggle italic          |
| `Ctrl+U`       | `Cmd+U`       | Toggle underline       |
| `Ctrl+Shift+X` | `Cmd+Shift+X` | Toggle strikethrough   |
| `Ctrl+E`       | `Cmd+E`       | Toggle code formatting |

#### Heading Shortcuts

| Windows/Linux | macOS       | Action               |
| ------------- | ----------- | -------------------- |
| `Ctrl+Alt+1`  | `Cmd+Alt+1` | Apply Heading 1      |
| `Ctrl+Alt+2`  | `Cmd+Alt+2` | Apply Heading 2      |
| `Ctrl+Alt+3`  | `Cmd+Alt+3` | Apply Heading 3      |
| `Ctrl+Alt+0`  | `Cmd+Alt+0` | Convert to paragraph |

#### List Shortcuts

| Windows/Linux  | macOS         | Action               |
| -------------- | ------------- | -------------------- |
| `Ctrl+Shift+8` | `Cmd+Shift+8` | Toggle bullet list   |
| `Ctrl+Shift+7` | `Cmd+Shift+7` | Toggle numbered list |

#### History Shortcuts

| Windows/Linux              | macOS                    | Action |
| -------------------------- | ------------------------ | ------ |
| `Ctrl+Z`                   | `Cmd+Z`                  | Undo   |
| `Ctrl+Shift+Z` or `Ctrl+Y` | `Cmd+Shift+Z` or `Cmd+Y` | Redo   |

### Screen Reader Support

The editor provides live announcements for all formatting actions and state changes to keep screen reader users informed of their actions.

#### Formatting Announcements

When users apply formatting through toolbar buttons or keyboard shortcuts, the editor announces:

- **Text Formatting**: "Bold applied", "Italic removed", "Underline applied", etc.
- **Headings**: "Heading 1 applied", "Heading 2 applied", "Paragraph style applied"
- **Lists**: "Bullet list applied", "Numbered list applied", "List removed"
- **Alignment**: "Left aligned", "Center aligned", "Right aligned", "Justified"
- **Code**: "Code formatting applied", "Code formatting removed"
- **Links**: "Link added", "Link removed"
- **History**: "Undo", "Redo"

#### State Announcements

The editor announces important state changes:

- **Disabled State**: "Editor disabled" when the editor becomes disabled
- **Enabled State**: "Editor enabled" when the editor is re-enabled
- **Read-Only State**: "Editor is read-only" when set to readonly mode
- **Editable State**: "Editor is editable" when readonly mode is removed

Announcements use ARIA live regions with `aria-live="polite"` to avoid interrupting screen reader output, and clear automatically after 1 second to prevent clutter.

### ARIA Attributes

The editor implements comprehensive ARIA semantics for assistive technology:

#### Toolbar

- `role="toolbar"` with `aria-label="Rich text editor toolbar"`
- `aria-orientation="horizontal"` for horizontal button layout
- `aria-controls` references the content area ID

#### Toolbar Buttons

- Descriptive `aria-label` attributes for each button (customizable via component properties)
- `aria-pressed="true"` when formatting is active at cursor position
- `aria-keyshortcuts` attributes documenting keyboard shortcuts (e.g., "Control+B" for bold)
- `aria-controls` references the content area ID

#### Content Area

- `role="textbox"` with `aria-multiline="true"`
- `aria-label="Editor content"`
- `aria-readonly` when in readonly mode
- `aria-disabled` when disabled
- Generated unique ID referenced by toolbar's `aria-controls`

#### Link Popover

- Focuses input field automatically when opened
- `Enter` key applies the link
- `Escape` key cancels and closes popover
- Pre-fills with existing link URL when editing

### Focus Management

- Clear, visible focus indicators on all interactive elements (provided by Forge components)
- Logical focus order: toolbar buttons → content area
- Focus returns to editor after toolbar actions
- No keyboard traps - users can always Tab out of the editor
- Popover input receives automatic focus when opened
- Input text auto-selects for easy editing

### Semantic HTML

- Headings use proper semantic HTML (`<h1>`, `<h2>`, `<h3>`) for screen reader navigation
- Lists use semantic `<ul>` and `<ol>` elements
- Links use semantic `<a>` elements with proper href attributes
- Content structure is meaningful without CSS

### Customization for Accessibility

All button labels can be customized to match your application's language or terminology:

```html
<forge-rte-standard-tools
  bold-label="Make text bold"
  italic-label="Make text italic"

  h1-label="Large heading"
  h2-label="Medium heading"

  align-left-label="Align text left"
  align-center-label="Center text"
  align-right-label="Align text right"
  align-justify-label="Justify text">
```

### Accessibility Best Practices

When using the rich text editor in your application:

1. **Provide Clear Context**: Use labels or instructions to describe the editor's purpose
2. **Error Handling**: Provide accessible error messages for validation failures
3. **Required Fields**: Use proper `aria-required` or required indicators on the containing form element
4. **Character Limits**: Announce character limits and remaining characters to screen reader users
5. **Disabled State**: Ensure there's a clear reason communicated when the editor is disabled
6. **Focus Indicators**: Don't override or hide the default focus indicators
7. **Testing**: Test with actual screen readers (NVDA, JAWS, VoiceOver) and keyboard-only navigation
