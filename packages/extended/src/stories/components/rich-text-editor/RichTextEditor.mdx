The `<forge-rich-text-editor>` component provides a powerful and accessible rich text editing experience powered by [TipTap](https://tiptap.dev/). It offers a flexible, component-based architecture where editing features are added as child components, allowing you to compose exactly the functionality your application needs.

The editor supports both standalone usage (with toolbar inline) and composed usage (with toolbar separated from content), making it adaptable to various UI layouts.

## Getting Started

### Installation

The rich text editor is part of the `@tylertech/forge-extended` package:

```bash
npm install @tylertech/forge-extended
# or
pnpm add @tylertech/forge-extended
```

**Peer Dependencies:**

The editor requires `@tylertech/forge` as a peer dependency:

```bash
npm install @tylertech/forge
# or
pnpm add @tylertech/forge
```

### Basic Setup

Import the components you need in your application:

```typescript
// Import the main editor component
import '@tylertech/forge-extended/rich-text-editor';

// Import the standard toolbar features
import '@tylertech/forge-extended/rich-text-editor/features/rte-standard-tools';

// Optional: Import additional features
import '@tylertech/forge-extended/rich-text-editor/features/rte-code';
import '@tylertech/forge-extended/rich-text-editor/features/rte-link';
```

### Your First Editor

Create a basic rich text editor with standard formatting tools:

```html
<forge-rich-text-editor>
  <forge-rte-standard-tools></forge-rte-standard-tools>
</forge-rich-text-editor>
```

That's it! The editor is now ready to use with headings, bold, italic, underline, strikethrough, lists, and text alignment.

### Listening to Changes

The editor emits a `change` event whenever content is modified:

```typescript
const editor = document.querySelector('forge-rich-text-editor');

editor.addEventListener('change', event => {
  const htmlContent = event.detail;
  console.log('Content changed:', htmlContent);

  // Save to your backend, update state, etc.
  saveContent(htmlContent);
});
```

### Getting Content

Retrieve content in different formats:

```typescript
const editor = document.querySelector('forge-rich-text-editor');

// Get HTML output
const htmlContent = editor.toHTML();
console.log('HTML:', htmlContent);

// Get JSON output (ProseMirror document structure)
const jsonContent = editor.toJSON();
console.log('JSON:', jsonContent);
```

### Setting Initial Content

Provide initial content via the `content` property:

```html
<forge-rich-text-editor content="<h1>Welcome</h1><p>Start editing here...</p>">
  <forge-rte-standard-tools></forge-rte-standard-tools>
</forge-rich-text-editor>
```

Or programmatically:

```typescript
const editor = document.querySelector('forge-rich-text-editor');
editor.content = '<p>New content here</p>';
```

## Features

The rich text editor follows a compositional pattern where you add feature components as children. Each feature component provides specific editing capabilities and registers itself with the editor.

### Available Features

#### Standard Tools (`<forge-rte-standard-tools>`)

The standard tools component provides common formatting features:

- **Bold**: Apply bold formatting to selected text
- **Italic**: Apply italic formatting to selected text
- **Underline**: Apply underline formatting to selected text
- **Strikethrough**: Apply strikethrough formatting to selected text
- **Bulleted List**: Create unordered lists
- **Numbered List**: Create ordered lists
- **Headings**: Format text as heading levels 1, 2, or 3
- **Text Alignment**: Align text left, center, right, or justify

The standard tools component exposes each feature through properties that allow you to customize labels for accessibility:

```html
<forge-rte-standard-tools
  bold-label="Make text bold"
  h1-label="Large heading"
  h2-label="Medium heading"
  h3-label="Small heading"
  align-left-label="Align left"
  align-center-label="Align center"
  align-right-label="Align right"
  align-justify-label="Justify text">
</forge-rte-standard-tools>
```

#### Additional Features

- **Code** (`<forge-rte-code>`): Inline code formatting with monospace styling
- **Link** (`<forge-rte-link>`): Insert and edit hyperlinks with URL validation
- **Divider** (`<forge-rte-feature-divider>`): Visual separator between feature groups

### Headings Feature

The rich text editor supports three levels of headings (H1, H2, H3) through the standard tools component. Each heading level has:

- A dedicated button with a unique icon
- Active state indication when the cursor is in a heading
- Customizable accessible labels
- Toggle behavior (clicking the active heading button converts back to paragraph)

Headings follow proper semantic HTML structure and can be styled consistently with your application's typography system.

## Best Practices

### Performance Considerations

The editor is optimized for documents up to 10,000 words and handles large content efficiently:

- ✅ **Large Documents:** Tested with 10,000+ word documents, loads in under 2 seconds
- ✅ **Smooth Typing:** No lag during rapid typing (100+ updates per second)
- ✅ **Memory Efficient:** No memory leaks during repeated mount/unmount cycles
- ✅ **Fast Output:** JSON/HTML generation completes in under 50ms

**Tips for optimal performance:**

1. **Use `toJSON()` for storage** - More compact than HTML, faster to parse
2. **Avoid frequent content updates** - Let users edit naturally, don't sync on every keystroke
3. **Use character limits** - Prevent extremely large documents that may impact UX
4. **Debounce autosave** - Save changes every few seconds, not on every keystroke

```typescript
// Good: Debounced autosave
let saveTimer;
editor.addEventListener('change', () => {
  clearTimeout(saveTimer);
  saveTimer = setTimeout(() => {
    saveContent(editor.toJSON());
  }, 2000); // Save 2 seconds after user stops typing
});
```

### Accessibility Best Practices

The editor is WCAG 2.1 Level AA compliant out of the box. To maintain accessibility:

1. **Provide Context:** Add a label or description explaining the editor's purpose
2. **Validate Accessibly:** Use the built-in validation system with clear error messages
3. **Test with Keyboard:** Ensure all functionality is accessible without a mouse
4. **Test with Screen Readers:** Verify announcements work correctly (NVDA, JAWS, VoiceOver)
5. **Don't Override Focus Indicators:** Keep the default focus styling visible
6. **Communicate State Changes:** Use the validation event to inform users of state changes
7. **Set Character Limits:** Help users understand content constraints before they exceed them

```html
<!-- Good: Clear labeling and validation -->
<div>
```

### Security Considerations

The editor includes security features to protect against XSS and other vulnerabilities:

1. **Paste Sanitization:** Pasted HTML is automatically sanitized to remove:
   - Scripts and event handlers
   - Iframes, embeds, and objects
   - Form elements
   - Dangerous attributes (onclick, onerror, etc.)

2. **Link Security:** Links automatically include security attributes:
   - `target="_blank"` - Opens in new tab
   - `rel="noopener noreferrer nofollow"` - Security and SEO protection

3. **Content Sanitization:** All user input is processed through TipTap's schema, which only allows whitelisted elements and attributes

**Best practices:**

```typescript
// Always sanitize content on the server side too
app.post('/save-content', (req, res) => {
  const content = sanitizeHTML(req.body.content); // Server-side validation
  saveToDatabase(content);
});
```

## Troubleshooting

### Common Issues

#### Editor doesn't appear or is not styled

**Problem:** The editor renders but looks unstyled or broken.

**Solution:** Ensure Forge CSS is loaded in your application:

```html
<link rel="stylesheet" href="node_modules/@tylertech/forge/dist/forge.css" />
```

Or import it in your JavaScript/TypeScript:

```typescript
import '@tylertech/forge/dist/forge.css';
```

#### Content changes not detected

**Problem:** The `change` event doesn't fire when content is updated.

**Solution:** Make sure you're listening to the correct event and the editor is properly initialized:

```typescript
const editor = document.querySelector('forge-rich-text-editor');

// Wait for initialization
editor.addEventListener('initialized', () => {
  console.log('Editor ready');

  editor.addEventListener('change', event => {
    console.log('Content changed:', event.detail);
  });
});
```

#### Toolbar buttons don't show active state

**Problem:** Bold, italic, or other format buttons don't highlight when the cursor is in formatted text.

**Solution:** This usually happens if features aren't properly registered. Ensure you've imported the feature components:

```typescript
import '@tylertech/forge-extended/rich-text-editor/features/rte-standard-tools';
```

And that they're included in the HTML:

```html
<forge-rich-text-editor>
  <forge-rte-standard-tools></forge-rte-standard-tools>
</forge-rich-text-editor>
```

#### Pasted content loses formatting

**Problem:** When pasting from Word or other sources, formatting is stripped.

**Solution:** Check the `allow-paste-formatting` property:

```html
<forge-rich-text-editor allow-paste-formatting="true">
  <forge-rte-standard-tools></forge-rte-standard-tools>
</forge-rich-text-editor>
```

Note: Some complex formatting (like Word's advanced styles) may still be simplified to maintain consistent output.

#### Link popover doesn't open

**Problem:** Clicking the link button doesn't open the URL input popover.

**Solution:** Ensure you've imported the link feature component and Forge popover:

```typescript
import '@tylertech/forge-extended/rich-text-editor/features/rte-link';
import '@tylertech/forge/popover'; // Required dependency
```

#### Content gets cut off at character limit

**Problem:** Users can't tell they've reached the character limit.

**Solution:** Enable character count display and provide clear error messages:

```html
<forge-rich-text-editor max-length="1000" show-character-count error-message="Content cannot exceed 1,000 characters">
  <forge-rte-standard-tools></forge-rte-standard-tools>
</forge-rich-text-editor>
```

## Accessibility

The rich text editor is designed to meet WCAG 2.1 Level AA compliance with comprehensive keyboard navigation, screen reader support, and proper ARIA semantics.

### Keyboard Navigation

All editor functionality is accessible via keyboard without requiring a mouse. The editor supports standard Tab navigation through toolbar buttons and intuitive keyboard shortcuts for formatting.

### Screen Reader Support

The editor provides live announcements for all formatting actions and state changes to keep screen reader users informed of their actions.

#### Formatting Announcements

When users apply formatting through toolbar buttons or keyboard shortcuts, the editor announces:

- **Text Formatting**: "Bold applied", "Italic removed", "Underline applied", etc.
- **Headings**: "Heading 1 applied", "Heading 2 applied", "Paragraph style applied"
- **Lists**: "Bullet list applied", "Numbered list applied", "List removed"
- **Alignment**: "Left aligned", "Center aligned", "Right aligned", "Justified"
- **Code**: "Code formatting applied", "Code formatting removed"
- **Links**: "Link added", "Link removed"
- **History**: "Undo", "Redo"

#### State Announcements

The editor announces important state changes:

- **Disabled State**: "Editor disabled" when the editor becomes disabled
- **Enabled State**: "Editor enabled" when the editor is re-enabled
- **Read-Only State**: "Editor is read-only" when set to readonly mode
- **Editable State**: "Editor is editable" when readonly mode is removed

Announcements use ARIA live regions with `aria-live="polite"` to avoid interrupting screen reader output, and clear automatically after 1 second to prevent clutter.

### ARIA Attributes

The editor implements comprehensive ARIA semantics for assistive technology:

#### Toolbar

- `role="toolbar"` with `aria-label="Rich text editor toolbar"`
- `aria-orientation="horizontal"` for horizontal button layout
- `aria-controls` references the content area ID

#### Toolbar Buttons

- Descriptive `aria-label` attributes for each button (customizable via component properties)
- `aria-pressed="true"` when formatting is active at cursor position
- `aria-keyshortcuts` attributes documenting keyboard shortcuts (e.g., "Control+B" for bold)
- `aria-controls` references the content area ID

#### Content Area

- `role="textbox"` with `aria-multiline="true"`
- `aria-label="Editor content"`
- `aria-readonly` when in readonly mode
- `aria-disabled` when disabled
- Generated unique ID referenced by toolbar's `aria-controls`

#### Link Popover

- Focuses input field automatically when opened
- `Enter` key applies the link
- `Escape` key cancels and closes popover
- Pre-fills with existing link URL when editing

### Focus Management

- Clear, visible focus indicators on all interactive elements (provided by Forge components)
- Logical focus order: toolbar buttons → content area
- Focus returns to editor after toolbar actions
- No keyboard traps - users can always Tab out of the editor
- Popover input receives automatic focus when opened
- Input text auto-selects for easy editing

### Semantic HTML

- Headings use proper semantic HTML (`<h1>`, `<h2>`, `<h3>`) for screen reader navigation
- Lists use semantic `<ul>` and `<ol>` elements
- Links use semantic `<a>` elements with proper href attributes
- Content structure is meaningful without CSS

### Accessibility Best Practices

When using the rich text editor in your application:

1. **Provide Clear Context**: Use labels or instructions to describe the editor's purpose
2. **Error Handling**: Provide accessible error messages for validation failures
3. **Required Fields**: Use proper `aria-required` or required indicators on the containing form element
4. **Character Limits**: Announce character limits and remaining characters to screen reader users
5. **Disabled State**: Ensure there's a clear reason communicated when the editor is disabled
6. **Focus Indicators**: Don't override or hide the default focus indicators
7. **Testing**: Test with actual screen readers (NVDA, JAWS, VoiceOver) and keyboard-only navigation
